Character relationships

A proposal for tracking who matters to whom. Relationships are added on a character's card and drawn as a chart beside the roster. Everything here is clickable: pick a character, pick a line, try Edit. The cast is The Drowned Map sample, plus Ione (Wren's mother) and one archived character, Captain Dace, so the chart has something to show.

Drag characters to arrange them. Click one to see their ties, or a line to read it.
The chart is the Characters drawer's second view. A Roster / Chart switch sits in the drawer header, and Chart opens the drawer full width (the existing Expand size), because a chart does not fit in 460px. One line per pair, colored by kind and always labeled, so color is never the only cue. Try dragging Pip into the middle.
  • Drag characters anywhere. Where you put them is saved in the project, like chapter cards on the board, so the chart looks the same on your other devices. Arrow keys move a selected character too. A press that doesn't move is a click, so clicking still works.
  • Start from a ring. Anyone you haven't moved sits on a ring in roster order (Wren, Bram, Ione, Sela, Pip, the same order as the tiles). Arrange in a ring (top right, once you've moved someone) puts everyone back.
  • Clicking a character highlights their ties and dims the rest. Nothing moves, so your arrangement stays put.
  • Labels never overlap. Each label takes the first free spot along its line, then just beside it, clear of every character and every other label. They re-place as you drag.
  • Kind filters in the side panel hide whole kinds of tie. Archived characters are off by default (screen 4).
  • Kinds are yours. "Edit kinds" (side panel, or in the editor) opens the project's list: rename, recolor, add or remove. The six here are only the starter set. Try renaming Rival, or adding "Debt". "Save as default" keeps your list for new projects, the way Author details does.
  • The side panel shows the selected pair or character. Each pair has a line for how each one sees the other, because feelings are rarely mutual.

The cards follow the detail-card restyle, which Ray has chosen (option B): each character is a tile with the chapter card's face, and clicking it opens the character in a window instead of expanding it in the list. The Relationships field lives in that window, under "Appears in". Each row names the other character, the kind, the label and both points of view, and clicking a row opens the editor on top of the window. "See on chart" closes the window and switches to the chart with this character in the middle. Click any tile here to open its window.
  • Tile face: initials badge in the character's color, role tag, name, two lines of description, and a footer of archetype · chapters, plus a relationship count in green. Optional
  • Grip and position number at the start of each tile come from the separate plan for rearranging cards. That plan isn't decided yet; they're shown so the pieces line up.
  • A pair is one record, so the tie shows in both windows (Wren's and Sela's), and editing either one edits the same tie.
  • Wren is already tied to everyone, so "+ Add relationship" in her window greys out the whole picker. That is the one-record-per-pair rule at work. To try adding, open Bram or Ione.
One small dialog for adding and editing, in the style of Estoria's confirm dialog. It opens on top of the character window, so it stacks one level higher than the restyle's window. Shown here: adding a tie from Bram's window, with Sela picked. The picker greys out anyone Bram already has a tie with, since a pair has one record. Click the dialog to try it live; it also opens from "+ Add relationship" on any card or in the chart, and from any tie row (as Edit, with Remove).
  • Kind comes from the project's own list and sets the color. Every project starts with Family, Friend, Romance, Mentor, Rival and Other; "Edit kinds" changes the list without leaving the editor. "No kind" is allowed. Label is free text for the specifics ("former mentor", "sisters").
  • Both points of view are optional. Leave one blank for a tie only one of them feels, or write "doesn't know she exists".
  • Changes over the story is shown greyed as a question, not a decision. It would let a tie turn at a chapter ("rival from Ch 3"). See the open questions.

Lines appear here as you connect your characters.

Open a character's card on the roster and use Add relationship. Each one you add shows up here as a line between two people.

Archiving keeps relationships, following Estoria's archive rule: Captain Dace leaves the roster and the picker, but his tie to Bram is kept and drawn dimmed and dashed when "Show archived" is on. Restoring him brings it back unchanged. Deleting a character removes their relationships too, and the delete confirm says how many ("They will be removed from 6 chapters and 1 relationship"). The empty state is plain and points at the one place relationships are added.
In the project file

Three new fields, next to characters

// StoryDoc gains two optional top-level fields
relationships?: Relationship[]
relationshipKinds?: RelationshipKind[]  // absent = the starter six
relationshipLayout?: Record<string, { x: number; y: number }>
                     // character id: where you dragged them,
                     // 0-1 across and down the chart

interface RelationshipKind {
  id: string;        // starter kinds keep fixed ids: "family", "rival", ...
  name: string;      // "Rival", or whatever you rename it to
  color: number;     // one of 10 palette swatches, 1-10
}

interface Relationship {
  id: string;        // its own id, so merge treats it as a unit
  a: string;         // character id
  b: string;         // character id (a != b, one record per pair)
  kind?: string;     // a RelationshipKind id; missing = No kind
  label?: string;    // "former mentor"
  aView?: string;    // how a sees b
  bView?: string;    // how b sees a
  notes?: string;
}

// Example
{ "id": "rel-k3x9", "a": "sela", "b": "wren",
  "kind": "mentor", "label": "former mentor",
  "aView": "Still sees her apprentice.",
  "bView": "Owes her everything, trusts her with nothing." }
What it touches

Sync, merge and the phone

  • No schema bump. The field is optional, like manuscript, author and pace before it. A file without it is a project with no relationships.
  • Series-wide. It sits beside characters, not on a book or version board, so every book in a series shares it and the phone needs no update first.
  • The phone keeps it. Android's normalize starts from the raw file and only overwrites keys it knows, so the list round-trips untouched. It just isn't shown there.
  • Chart positions live in the project, like chapter positions on the board. Only characters you've moved have one; the rest sit on the ring. Positions are fractions of the chart, so they fit any drawer width. Positions for deleted characters are dropped on read.
  • Kinds live in the project. Absent means the starter six. The first edit writes the whole list. Starter kinds keep fixed ids, so two devices that never edited agree.
  • Read defensively. A tie whose character is gone (deleted on the phone, say) is dropped on read, as is a tie to itself or a second record for the same pair. A tie whose kind was removed is kept and shows as No kind.
  • Conflicts and merge. Each relationship becomes its own row in the compare and merge dialog, and the kind list and the chart layout are one row each, taken whole. Taking a relationship from the file brings in both characters it points at, and its kind if this copy lacks it.
  • Delete cleans up. Deleting a character removes its relationships; archiving keeps them.
